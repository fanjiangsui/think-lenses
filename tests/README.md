# 測試

兩支腳本，一個指令跑完：

| 檔案 | 做什麼 | 需要瀏覽器 |
|---|---|---|
| `lint_pack.py` | 檢查 `data/philosophers.json`：必填欄位、每面鏡頭都有盲點與不適用情況、引用的 id 都存在、每種類型至少 2 面鏡頭、中文旁不得有半形標點、不得有開發備註；**輕量模式的安全規則**：不得把「低落或自責時不宜」的鏡頭放進輕量池 | 否 |
| `e2e.py` | 端對端：開啟 app、走完整流程、模擬「手機」與「Mac」兩個獨立環境互相備份合併 | 是(Chromium) |
| `run.sh` | 依序執行以上兩者 | |

## 安裝(只需一次)

```bash
python3 -m pip install -r tests/requirements.txt
python3 -m playwright install chromium    # 需要網路，下載測試用的 Chromium
```

## 執行

```bash
bash tests/run.sh                          # 內容檢查 + 端對端(自動在本機起伺服器)
bash tests/run.sh --shots tests/out        # 同時輸出截圖(淺色與深色)到 tests/out
bash tests/run.sh --headed                 # 顯示瀏覽器視窗，方便除錯
python3 tests/lint_pack.py                 # 只檢查內容(改 JSON 時最快)
```

**測試已部署的網站**(只送出讀取請求，不會寫入伺服器)：

```bash
python3 tests/e2e.py --url https://<你的帳號>.github.io/think-lenses/
```

任何一項失敗，或出現 console 錯誤(含 CSP 違規)，指令會以非 0 結束。測試用的是全新的暫時瀏覽器環境，**不會碰你真實瀏覽器裡的紀錄**。

## 這些測試有用嗎？

我另外做過「故意改壞」驗證(新增的安全功能有 8 種：備份宣稱加密卻輸出明文、鎖定守門被拿掉、輸錯不再鎖住、PIN 明文儲存、復原時間不比墓碑新、墓碑保留內容、背景不再遮蔽、解密不驗證 KDF 次數上限)。其中「復原時間不比墓碑新」第一次**沒有被抓到**，原因是測試種子的時間比現在還晚，比較剛好成立；已改成過去的時間並重新驗證。其餘：合併比較方向反轉、移除轉義、刪除時不清空內容、`ASSETS` 加不存在的檔案、內容包被弄壞、輕量模式的四種改壞(池子不再過濾、問題不再過濾、當天就回訪、問題上限放寬)、「卡繆被放進輕量池」，以及新入口的六種(聊聊偷偷寫入紀錄、風暴用到全部鏡頭、今日一顆每天都一樣、首頁拿掉一句話說明、風暴沒輸入也建立紀錄、今日一顆池含不適合的鏡頭)，測試都會失敗。

注意：部分改壞會讓測試因為等不到預期畫面而中斷(結束碼非 0)，同樣視為失敗。

注意：惡意 HTML 有兩層防護(轉義，加上 CSP 擋掉行內腳本)。移除轉義時，測試是靠「console 出現錯誤」抓到的，因為 CSP 先擋下了執行。

另外修正了測試本身的一個時序問題：點導覽後只等 `.rows .row`，而前一頁也有同樣元素，偶爾會在頁面切換前就開始斷言。現在改成等該頁的標題或專屬元素。

## 沒有涵蓋(需要實機)

- 只測 Chromium。Safari(iOS、macOS)與 Firefox 沒測。
- iOS 的「分享備份檔」面板、加到主畫面後的外觀、iOS 清除網站資料的行為。
- 視覺品質(截圖要用眼睛看)。首頁在 844 像素高的手機上，第 4、5 個入口需要往下捲才看得到。
- 背景遮蔽與自動鎖定，是用程式模擬「頁面進入背景」的事件，並非真的切換 app；實機行為(含多工切換畫面)沒有驗證。
- iOS Safari 的分享檔案是否接受「先加密再分享」的流程。
- PBKDF2 在舊手機上的耗時。
- 「請求持久儲存」是否被瀏覽器同意。

## 修改後怎麼維持

- 改了 `data/philosophers.json`：先跑 `python3 tests/lint_pack.py`。
- 改了程式或新增功能：在 `e2e.py` 加一個 `check(...)`，再跑 `bash tests/run.sh`。
- 驗證環境：Playwright 1.56.0、Chromium 141。其他版本我沒測。
